# Práticas de XP Adotadas

## 1. Pair Programming

Dois desenvolvedores trabalham juntos na mesma tarefa, aumentando a qualidade do código e promovendo compartilhamento de conhecimento.

## 2. Integração Contínua

As alterações são integradas frequentemente ao repositório, permitindo identificar problemas rapidamente.

## 3. Design Simples

O sistema será desenvolvido apenas com funcionalidades realmente necessárias para cada Sprint.

## 4. Refatoração Contínua

O código será constantemente melhorado para manter simplicidade, legibilidade e facilidade de manutenção.

## 5. Pequenas Entregas

As funcionalidades serão entregues em partes menores e utilizáveis, permitindo feedback rápido do cliente.



# Integração entre XP e Scrum

O Scrum será utilizado para organizar o trabalho por meio de Sprints, planejamento, acompanhamento e retrospectivas.

O XP fornecerá práticas técnicas para garantir qualidade durante o desenvolvimento, como Pair Programming, Integração Contínua, Refatoração e Design Simples.

Dessa forma, Scrum organiza o processo e XP melhora a execução técnica das atividades.



# Fluxo Semanal da Equipe

## Sprint Planning

Realizada no início da Sprint para selecionar os itens do Product Backlog que serão desenvolvidos.

## Daily Scrum

Reunião diária de aproximadamente 15 minutos para acompanhamento das atividades.

## Desenvolvimento

Durante a Sprint são aplicadas as práticas de XP para garantir qualidade e evolução contínua do produto.

## Sprint Review

Realizada ao final da Sprint para apresentar as funcionalidades concluídas ao Product Owner.

## Sprint Retrospective

Reunião de melhoria contínua para identificar pontos positivos e oportunidades de aprimoramento.



# Cronograma de Sprint de 2 Semanas

| Período       | Atividade                              |
| ------------- | -------------------------------------- |
| Dia 1         | Sprint Planning (2 horas)              |
| Dias 1 a 10   | Desenvolvimento das funcionalidades    |
| Todos os dias | Daily Scrum (15 minutos)               |
| Dias 2 a 10   | Pair Programming e Integração Contínua |
| Dias 3 a 10   | Refatoração e melhorias contínuas      |
| Dia 10        | Sprint Review (1 hora)                 |
| Dia 10        | Sprint Retrospective (1 hora)          |

# Comparação entre Scrum e Kanban

| Aspecto                   | Scrum                       | Kanban               |
| ------------------------- | --------------------------- | -------------------- |
| Estrutura                 | Baseado em Sprints          | Fluxo contínuo       |
| Planejamento              | Ocorre no início da Sprint  | Contínuo             |
| Mudanças durante execução | Limitadas                   | Flexíveis            |
| Métricas principais       | Velocidade da Sprint        | Tempo de ciclo       |
| Reuniões                  | Possui cerimônias definidas | Não exige cerimônias |

## Quando Utilizar Scrum

* Projetos com objetivos definidos.
* Equipes que trabalham em ciclos de entrega.
* Necessidade de planejamento estruturado.

## Quando Utilizar Kanban

* Demandas contínuas.
* Equipes de suporte ou manutenção.
* Necessidade de alta flexibilidade.

## Como Podem Ser Combinados

Uma equipe pode utilizar Scrum para organizar as Sprints e Kanban para visualizar o fluxo das atividades dentro de cada Sprint, obtendo benefícios de ambas as abordagens.

## Conclusão

A combinação de Scrum e XP permite organizar o trabalho de forma eficiente, enquanto o Kanban fornece transparência sobre o andamento das atividades. Essa integração contribui para entregas frequentes, qualidade do software e adaptação rápida às mudanças.
